# Synthetic challenge review standard — version 1 (2026-09-29)

This page states how Civic Continuum evaluates the *fictional force-trace exercise*. It is an educational review process, not certification, endorsement, flight readiness, a measurement of thrust, or a prize competition. No institution or outside researcher is represented as approving the project. The public contribution board reports moderation and reproduction status only.

## What qualifies for review

- A specific, original critique or small fictional CSV rows pasted as plain text in a `[Challenge]` issue, with a way to reproduce the reasoning using the repository's own script or by hand.
- An explicit ordinary explanation, missing channel, or falsifying observation.
- No files, external links, scripts, patches, executable content, real instrument data, confidential design, personal details, or third-party material without permission.

An automated text rule closes some issues containing link, archive, patch or command cues without a public reply. It does not open or scan file bytes and is **not antivirus**. It can miss unsafe material or close harmless text. A maintainer must still screen issues and reports. Public GitHub history and notifications may persist after closure.

## Review sequence

1. **Screen:** Check the plain-text issue for privacy, rights, unsafe instructions, relevance and the author's credit choice. Only a maintainer can add `reviewed-entry`; an issue is invisible on the board until that label and `Public credit: yes` are both present.
2. **Reproduce:** Compare the claimed result with the unchanged example data and script. A missing artifact channel is **inconclusive**, not evidence of thrust. Test ordinary artifact explanations and specify a null or counterexample. No contributor code or attachment is executed.
3. **Record:** Add `validated-counterexample` only if the *fictional-data critique* is independently reproducible. State the scope of the result. Edits to reviewed issues revoke review labels and require a new screen.
4. **Separate decision:** A reviewed link may enter a private human review queue. It is never automatically implemented in private code or converted into a physical claim. The organizer can reject, close, or withdraw a public board listing.

## Evidence boundaries

| Status | What it means | What it does not mean |
|---|---|---|
| Submitted | A public GitHub issue exists | Safe, original, accepted, or scientifically sound |
| Reviewed entry | A maintainer screened the issue and the author opted into board credit | Reproduced, endorsed, or integrated |
| Validated counterexample | A fictional-data critique was reproduced independently | Physical propulsion, certification, patent clearance, or operational safety |

A future physical claim would require a separate written protocol, independent calibration, sham and environmental controls, uncertainty, independent operation, a tested emergency disconnect and stop criteria. Software tests alone cannot pass that gate.
